Your signing key

Every command is signed with an Ed25519 key kept on this machine
(key.seed in the configuration directory, readable only by you). A
repeater accepts commands signed by exactly one public key, the one
given to it over its serial console:

  set mqtt.cmd.pubkey <your 64-hex public key>
  set mqtt.cmd on

On the firmware of 2026-10-08 or later (ar-11) that second line does
the rest: with no slot configured the node takes its first free MQTT
slot (3-6), points it at the default broker mqtt.louie.se with the
built-in "mccontrol" preset, and says "reboot to apply". A board without
PSRAM runs two slots at once; if both are its analyzer uplinks, the node
says so and asks you to turn one off (set mqtt2.preset none) -- it never
does that for you. A region running its own broker sets the slot by
hand (set mqttN.preset custom, server, audience; set mqtt.cmd.slot N).

The Keys menu shows that command on one line, creates a key when there is
none, imports an existing seed, and replaces the key -- which silences
every repeater provisioned with the old one until each is re-provisioned.

The seed is never shown and never leaves the machine inside anything but
a signature. "refused: sig-invalid" from a node means it holds a
different public key than this one.

The same key signs you in to the default broker (see [[broker]]). Keys >
Register (or "mccontrol register") publishes your public key to the
broker once, signed by the key itself; from then on the broker checks
every command against the registered keys before it reaches any node,
and a login that keeps sending badly signed commands is locked out for
48 hours after five in a day. Register once per key, never per device.

See [[protocol]] for what the signature covers.

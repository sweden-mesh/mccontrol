Select Command

7=Commands on a row, or F4 on Send a Command, lists every command the
control plane admits, by group: reads, auto-reply, regions, tuning, MQTT,
node. Text typed on the Filter line narrows the list; Enter applies it.
The target is the row you typed 7 by; from Send a Command, the devices
named there.

Type 1 by a command and press Enter; 5 displays it: its group, the build
it needs, its examples and its caution. What 1 does depends on what the
command needs:

  nothing       it is sent at once and the results are shown (ver,
                region, reboot)
  one value     Select Value: 1 by one value, Enter sends
                (set autoreply on|off, set autoreply.mode ...)
  several       Select Value: 1 by each value wanted
  free text     Specify Value, with examples above it (region put
                se-jkp *, set txdelay 0.5); an empty value asks again

A command the device's firmware does not admit says so in the Admitted
column with the build it needs, and is not sent; the line above the
list says what the devices report (ar-10, or "unknown", which counts as
the oldest), and 11=Name and version reads it. F5 reads the list again.
The fleet runs several firmware versions for months, so this is how a
command slot is never spent on a not-allowed. ar-10, the build in the
field, admits the auto-reply settings, the two triggers and a dozen
reads; ar-11 admits everything on the deny list's far side (ver, get
name, get stats, the region map, the tuning writes, reboot...). To make
the list complete, flash.

A command that takes something away still asks first (see [[cautions]]),
and one the firmware would refuse is stopped before it is signed, with
the reason (see [[commands]]).

The full table, with each command's kind, is "mccontrol commands".

See [[send]], [[reads]] and [[keys]].
